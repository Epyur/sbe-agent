# AGENTS.md — sbe-agent (LogicTEAM.007)

Универсальный LLM-агент: MCP-набор тулов (создание/чтение Word/Excel/JSON/электронных PDF),
чтение баз (письма, документы, ЛИМС) по правам пользователя через соответствующие плагины
и локальной базы задач. Генерация файлов — на сервере (agent-service → S3 `sbe-agent` →
ссылка на скачивание ~2 дня).

**Бэк — в этой же папке** (`agent-service/` + `agent-mermaid/`, 2026-08-24, переехали из
`server_back/`) — на отдельной ветке `backend` (main — чистый релизный срез кода плагина,
без бэка; см. правило «Бэки в папках плагинов» в корневом `plugins/AGENTS.md`).

## Назначение (текущее)

- **MCP в Obsidian**: реестр тулов (MCP-совместимые схемы name/description/input_schema) +
  цикл агента (`src/agent/agent-engine.ts`): контекст → `sbe-llm.completeJson` →
  `{"type":"tool_call"|"final"}` → исполнение → повтор (до 6 итераций). Внешний MCP-сервер
  для сторонних клиентов — вне MVP.
- **Тулы файлов** — через agent-service (`JWT app_id=agent`): `create_docx`/`create_xlsx`/
  `create_pdf`/`create_json` (`POST /api/agent/file/generate`, spec → S3 `sbe-agent` → URL),
  `parse_file` (`POST /api/agent/file/parse`, multipart; чтение содержимого прикреплённого файла).
- **Тулы данных** — прямые вызовы plugin-services по JWT пользователя (права проверяет сервер,
  1:1 с плагинами): `get_emails` (mailer), `get_documents` (documents), `get_lims_requests` (lab),
  `get_tasks` (локальный кэш `yourbase/sbe_tasks/tasks_cache.json`, всегда доступен).
- **Контекст пользователя** — имя из настроек (`userName`) + email из ЦУП. Доступные источники —
  по `permissions/me` каждого app (сайдбар показывает уровень роли).
- **История диалогов** — `yourbase/sbe_agent/chat_history.json` (`{dialogs:[{id,title,messages,created_at,updated_at}]}`).
- **Точка входа** — магазин: «Установленные → Открыть» (`publishService('sbe-agent', {open})`).

## История работ

### 2026-08-27 — v0.2.14 (фикс 504/зависания: записи не идут через контекст LLM; чистка HTML в Excel)
- **Жалоба/диагноз**: при сборе НСОПБ (387 записей) агент на другой машине «зависал» — возвращал **504**.
  Причина: v0.2.13 заставлял модель САМУ передавать `records` страницы в `save_records_to_vault`.
  Записи реестра огромные (~2–7 КБ), 100 на страницу ≈ 220–700 КБ, транскрипт режет данные до
  30 КБ → модель видит лишь ~4–13 записей из 100, но инструкция требует сохранить всю страницу →
  модель выдаёт огромный JSON-вывод → генерация не успевает → `ask.chadgpt.ru` отвечает 504,
  а `LLMCenter.retryWithBackoff` ретраит 504 (3 × до 180 с) → «висение» на минуты.
- **Фикс**: записи больше НЕ проходят через контекст LLM:
  - **`fetch_url` получил параметр `save_to`** (`yourbase/sbe_agent/...`): при табличном JSON-ответе
    (DataTables) тул САМ дописывает `data` страницы в JSONL вольта и возвращает только счётчики +
    итог («сохранено N, всего в файле M»). В контекст записи не попадают → ответы модели маленькие.
  - Промпт: пагинация через `save_to` (start += data.length до recordsFiltered), «не переписывай
    записи в аргументы тулов», в конце `build_xlsx_from_vault`.
  - **Дедупликация** в `appendRecordsJsonl` — повторный запрос страницы (ретрай/таймаут) не
    добавляет дубли (проверено на живом сборе: 100+100+100+87=387 без повторов).
- **Чистка HTML-рудиментов в Excel** (жалоба: в скачанном xlsx теги `<br>`/`<a href>` и сущности
  `&quot;`/`&amp;`): в `build_xlsx_from_vault` каждая ячейка чистится — `<br>`→перенос строки,
  теги убираются (содержимое сохраняется), сущности → символы. Источники (реестры) отдают текст
  с вёрсткой — в Excel он теперь чистый.
- Проверено: tsc EXIT=0, build OK, чистка на реальных образцах, 504-сценарий устранён.
  Версия 0.2.13 → **0.2.14**.

### 2026-08-27 — v0.2.13 (сбор данных постранично: счётчики DataTables + накопление в файл вольта)
- **Фикс зависания на nsopb.ru** (диагноз v0.2.12, реализован по согласованной схеме):
  - `fetch_url` для JSON/API теперь извлекает **счётчики** (`recordsTotal`/`recordsFiltered`/
    `data.length`) + 2–3 примера записей вместо сырого превью — модель сразу видит
    «всего N / по фильтру M» и знает, когда заканчивать пагинацию (раньше счётчики лежали
    в КОНЦЕ больших ответов и не попадали в контекст). Полный массив `records` страницы
    отдаётся в `data` (для сохранения), превью в контекст не раздувает.
  - Если JSON повреждён/обрезан (серверный лимит 1 МБ при length>~500) — явная подсказка
    уменьшить `length` до 50–100.
  - **Новые тулы** (`src/agent/tools/records-tools.ts`):
    - `save_records_to_vault(path, records, mode?)` — накопление записей страницы в JSONL
      вольта (путь обязан начинаться с `yourbase/sbe_agent/`, `mode=overwrite` — начать
      заново); данные не живут в контексте, переживают «продолжай»;
    - `build_xlsx_from_vault(path, file_name?, sheet_name?, headers?)` — сбор Excel из
      накопленного файла целиком (читает файл, строит таблицу, возвращает ссылку);
      заголовки — из ключей объектов или `headers` (для строк-массивов — «Колонка N»).
  - **Промпт** (`renderSystemPrompt`): пошаговая инструкция сбора списков — умеренный
    `length=50–100` (большие ломаются о лимит 1 МБ), `start += data.length` до
    `recordsFiltered`, после каждой страницы `save_records_to_vault`, в конце
    `build_xlsx_from_vault`, не повторять одинаковые параметры.
- `npx tsc --noEmit` EXIT=0; `npm run build` OK. Версия 0.2.12 → **0.2.13**.

### 2026-08-27 — v0.2.12 (fetch_url: компактное представление HTML, анти-цикл для fetch)
- **Жалоба/диагноз (nsopb)**: агент сначала использовал fetch_url, но GET возвращал сырой
  HTML (106998 симв.), а LLM видел обрезок с `<head>/CSS` — не мог найти DataTables-эндпоинт
  `/ajax/datatables/reestr_documents.php`; 10+ раз перезапрашивал ту же страницу (fetch_url
  был исключён из анти-цикл-гарда в v0.2.11), транскрипт раздувался → LLM 400 (context
  length), затем 502.
- **Фиксы**:
  - `fetch_url` для HTML отдаёт **компактное представление** (`compactHtml`): SCRIPTS
    (URL подключаемых .js — там ищется DataTables/AJAX), LINKS, текст (~6К). JSON — сам JSON
    (усечён до 12К). Сырой HTML в контекст не попадает → транскрипт не раздувается.
    Проверено на nsopb.html: SCRIPTS содержит `/js/datatables/reestr_documents.js` → по нему
    агент находит `ajax.url: /ajax/datatables/reestr_documents.php`.
  - `fetch_url` **возвращён в анти-цикл-гард** (повторный запрос с теми же параметрами —
    детерминированный результат = зацикливание; браузерные навигационные тулы остались
    идемпотентными).
  - Промпт: пошаговая инструкция поиска AJAX-эндпоинта (script src → загрузка .js →
    ajax.url → POST с draw/start/length/search[value]/columns).
- `npx tsc --noEmit` EXIT=0; `npm run build` OK. Версия 0.2.11 → **0.2.12**.

### 2026-08-27 — v0.2.11 (скрытый серверный режим работы с сайтами — fetch_url; фиксы браузера)
- **Скрытый режим (по умолчанию)**: новый серверный `POST /api/agent/fetch`
  (`agent-service/fetch.go`) — HTTP-запрос (GET/POST/PUT/PATCH/DELETE, body, headers,
  timeout) с **SSRF-защитой** (запрет loopback/приватных/локальных адресов и редиректов
  на них; лимит ответа 1 МБ). Новый тул **`fetch_url`** в плагине — работа со страницами
  и JSON/API-эндпоинтами (в т.ч. DataTables: POST с `draw/start/length`+`search[value]`
  и `columns[...]`) БЕЗ браузера.
- **Браузер — только по запросу/авторизации**: промпт изменён — по умолчанию `fetch_url`
  (скрытый серверный режим); `browser_*` — только когда пользователь просит показать
  действия в браузере или требуется логин (тогда `browser_open` → `browser_wait`).
- **Фиксы движка**:
  - сообщение «Достигнут лимит повторных вызовов» заменено на понятное «Защита от
    зацикливания…» (это анти-цикл-гард, НЕ лимит шагов);
  - идемпотентные тулы навигации/чтения (`browser_open`, `browser_wait`, `browser_extract`,
    `browser_links`, `browser_screenshot`, `fetch_url`) исключены из анти-цикл-гарда
    (повтор одинакового вызова больше не обрывает сессию; предел даёт `maxIterations`).
- **Разведка nsopb.ru** (реестр НСОПБ): данные грузятся через DataTables
  `POST /ajax/datatables/reestr_documents.php` (нужны полные `columns[...]`);
  «кровля» → 387 записей, «огнестойкость» → 6004, «пожарная опасность» → 3. Причина
  провала агента в браузере — таблица грузится AJAX (extract ловил «Таблица
  формируется…»), `browser_links/type` падали с `GUEST_VIEW_MANAGER_CALL`
  (executeJavaScript на тяжёлой JS-странице), `browser_wait` ждал человека, а не
  загрузки. Серверный `fetch_url` это решает.
- Сервер: `agent-service/fetch.go` + роут (ветка `backend`, без бампа). E2E: GET страницы
  200, POST DataTables с поиском → JSON, SSRF localhost/auth-db → 400.
- `npx tsc --noEmit` EXIT=0; `npm run build` OK. Версия 0.2.10 → **0.2.11**.

  переключении вкладок.
- `browser-manager.ts` переведён на **host-модель**: вьюха регистрирует себя
  (`registerHost`), webview создаётся лениво (`ensureWebview`). `src/ui/browser-view.ts`

  с увеличивающимся `start` до «конца документа»). Файл переживает «продолжай» — можно дочитать
  документ в следующих запусках без повторного прикрепления. Подсказка в настройках: увеличить
  «Максимум шагов агента» для многочастного чтения.
- **Ленивый JSON-протокол** (устраняет массовые «Ошибка обращения к LLM» при разборе больших
  документов): движок берёт **сырой текст** ответа LLM (`complete`), лениво извлекает JSON
  (`tool_call`/`final`); если ответ не JSON — текст становится **финальным ответом** пользователю,
  без ошибки. Лимит результатов тулов в истории поднят 4000 → 15000 символов (продолжение диалога
  сохраняет больше содержимого документа). Промпт дополнен: JSON обязателен только для вызова
  инструмента, после больших документов можно ответить текстом.
- **Сервер** (`agent-service/skills.go`, ветка `backend`, без бампа версии плагина): таблица
  `skills`, эндпоинты списка/чтения/записи/удаления, валидация имени и файлов, лимит 8 МБ.
- `npx tsc --noEmit` EXIT=0; `npm run build` OK. Версия 0.2.5 → **0.2.6**.
